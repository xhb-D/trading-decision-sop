# Trading Decision SOP Dashboard V1 实施规范

授权基线：用户提供的《交易决策 SOP V1.1》执行命令与《SOP 使用效率监测 V1》补充命令，均明确要求本轮实施。原看板仅只读参考，新项目独立目录、构建、运行和数据。V1 是人工流程导航，不判断行情或执行交易。

## 业务规范

- P0 核对真实平台 → P1 人工 Bias → P2 人工结构 → P3 候选位置 → P4 人工 Setup → P5 人工风险/失效点确认与成交记录 → P6 持仓管理。导航不能绕过前置条件。
- 正式多/空禁止相反方向进入 P5；未裁决禁止 P5；两类中性分别由交易者对当前候选明确授予方向权限。每次机会独立，无时段唯一方向。Setup 不改 Bias。
- R01 仅对有效、已明确确认合格的候选到位，进入 P4。R02 保存原任务及依赖版本 → P2 局部更新 → 依赖仍有效则恢复，否则注销并路由上游；不改 Bias/原失效点。
- R03 空仓使当前候选的 Setup 重新观察，不授予位置准入；有持仓或委托时风险/撤单核对优先。R04 回 P3 评估候选方向，清除该候选旧 Setup 与权限；不改 Bias，不直接进入 P5。
- U0 维持；U1 只失效受影响候选的下游；U2 清理分析快照，保留真实持仓/委托及入场时的失效点，并要求平台核对。无持仓/委托时从 P1 重新读图。
- 候选独立保存，不排名。位置失效不删除其他候选。已有持仓优先 P6；仍可通过 R02 更新结构，处理后回 P6。单品种同时只管理一个实际执行计划；再次执行受阻，其他候选保留。跨品种总体风险由交易者在 P5 确认。
- 原理由失效：pending → cancelRequested；人工确认撤单结果后才能清除未成交部分。部分成交同时保留 position → P6，未成交部分须核对撤单。触及原逻辑失效点 → 要求平仓 → 人工确认平台已平仓；不自动认定成交/撤单/平仓，不支持放宽原点。
- 刷新后保留当前任务。存在真实敞口或挂单时强制平台核对；新日期或超过 8 小时离开视作“快照可能过期”，提示人工选择 U2 或核对继续，不能推断行情失效。
- 危险操作先确认；导入先验证、备份再替换，禁止以导入静默删除当前真实敞口；关闭统计日志不影响交易状态（V1 只提供清空，不提供采集开关）。

## 技术规范

- 纯静态 TypeScript + 原生 DOM + Vite；无运行时第三方依赖；浅深主题、桌面优先、窄屏兼容。URL 无路由依赖，Vite relative base 支持 Pages 子目录。
- engine.ts 是纯函数 reducer：只接收显式 Action，返回新状态、可审计路由事件；统一权限门，UI 不直接改业务状态。
- 每品种独立 Workflow，独立 taskId、候选依赖版本；R02 suspension 捕获原 stage/candidate/revision。执行计划和候选分离，真实敞口不因分析失效被清除。
- persistence.ts 只使用 trading-decision-sop:v1:* 名称空间；主状态与 analytics 同一 envelope 原子保存，滚动备用副本；损坏原文保存在隔离键，不能静默覆盖。未来版本拒绝导入，不猜测迁移。
- analytics.ts 从 reducer 的 Action 与路由事件生成 v1 日志；USER_ACTION 仅真人有效交互一次，自动路由不算点击。SESSION_STARTED 区分浏览器使用会话与市场 Session。
- 统计口径：taskId 是一次机会/恢复流程的任务。进入 P3 后新增候选即新任务；任务完成为人工平仓确认或明确失效注销，阶段完成另记 STAGE_COMPLETED。平均每任务点击以已完成且日志完整的任务为分母，未完成单列。
- 耗时为可观察“活跃操作估计”，不是心理决策耗时：显式 W 等待排除，后台排除，每次交互最多结算前 30 秒可见活跃时间；超过部分 idle 单列。键盘/指针活动自动唤醒，不额外要求用户确认。原始 DURATION_RECORDED 记录 active/wait/idle，可重算指标。刷新/品种切换断开旧计时，不跨会话计入离线时间。
- STAGE_REVISITED 根据任务已完成环节判断。市场事件的上游更新单列；用户无条件版本变化的上游返回标记“待人工复核”，不认定违规。只对可观察状态不变量异常记 WORKFLOW_EXCEPTION。
- 原始日志上限 4,000 条，同时保存前限制完整工作区约 900,000 字符，按有界前缀裁剪；不可完整保留的任务标记不完整并排除均值。界面和导出注明保留窗口、丢弃数。事件不含价格、备注、账号或订单号，仅系统 ID、品种、环节、动作代码和路由原因。
- 日期筛选按事件发生时浏览器本地日历日期；任务统计按任务开始日归属，日期窗口内缺失开始/结束的任务不算已完成均值。CSV 带原始事件及结构化计时，JSON 带事件和统计口径。

## Verification

自动测试覆盖原命令 20 个场景及补充命令 8 条验收，包含方向门、R02/R04 不变量、局部失效、部分成交、持仓保留、导入校验、日志容量与统计对账。浏览器验证主路径、等待、事件中断恢复、主题、刷新、分析筛选与窄屏；截图与验证记录独立保存。未完成真实盘中用户验收之前不标记 FROZEN。

## 参考与复用边界

公开参考 https://xhb-d.github.io/intraday-task-cards/#/home 已通过浏览器读取；本地源码只读检查 package.json、styles.css、appearance.js。仅参考色彩与层级，不复制业务模块和存储格式。选择原生 DOM 的原因是单页情境操作简单且运行时零依赖；自定义 reducer 承载用户确定的规则，避免通用向导替代路由语义。TypeScript DOM 文档：https://www.typescriptlang.org/docs/handbook/dom-manipulation.html；静态部署依据：https://vite.dev/guide/static-deploy.html。

## 补充授权：SOP Analytics Bundle

2026-10-26 用户要求一键导出版本化 Bundle。增加 rules.ts（SOP 1.1、routing 1.0.0 与显式规则快照），原始 v1 事件新增向后兼容的 SOP/规则版本字段及 STATE_CHANGED 事件。状态快照采用白名单，排除位置名称、价格与原逻辑点自由文本；保留候选/执行标记与状态引用。

Bundle v1 同时包含 rawLog、taskLifecycles、stateChanges、routes、upstreamReturns、ruleSnapshot、summary、retention 与 metricDefinitions。每次上游返回关联本任务上次进入目标环节（无则任务开始）之后的状态变化/已确认条件事件，逐个 ID 可回查。没有锚点或旧日志缺少快照时标记证据不足。不能从“无已记录变化”推出纪律违规。重算仅使用 rawLog，scripts/recompute-analytics.mjs 与自动测试执行全指标相等核验。

最终审查补充不变量：R01 必须先确认结构；风险事件离开 P2 时结束旧 R02 suspension；真实敞口期间允许回 P0 补录而不能绕过平台核对；候选独立保留 completedStages，切换不丢重访证据。
